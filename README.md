# WALEEDMMH App Center — المرحلة الثانية

موقع ثابت متعدد اللغات (العربية الافتراضية + الإنجليزية) يُولَّد من ملفات بيانات، مع **لوحة تحكم** في المتصفح، وإحصائيات مجهولة، وتقييمات بمراجعة، ونموذج دعم.

## الملفات
| الملف | الدور |
|---|---|
| `site.json` | اسم العلامة والبريد والروابط واللغات المفعّلة وحالة اعتماد سياسة الموقع |
| `*.app.json` | ملف لكل تطبيق (الآن: `waleed-adshield-mobile` و`waleed-targma`) |
| `ar.lang.json` / `en.lang.json` | نصوص الواجهة لكل لغة (وسياسة خصوصية الموقع) |
| `build.js` + `shared.js` | المولّد، والتحقق المشترك (نفس القواعد في البناء واللوحة) |
| `functions/api.mjs` | الواجهة الخلفية الوحيدة: الإدارة، التقييمات، الإحصائيات |
| `admin.html` + `admin.js` | لوحة التحكم على `/admin/` |
| `apk-reader.js` | قارئ APK يعمل في متصفح اللوحة (ولا يرفع الملف لأي مكان) |
| `media/` | الصور المرفوعة من اللوحة (أو ضع الصور في جذر المجلد كما قبل) |

## التشغيل لأول مرة (مرة واحدة)
1. ارفع كل الملفات إلى مستودع GitHub، **ومعها مجلد `functions`** (من الهاتف: Add file ← Create new file واكتب الاسم `functions/api.mjs` ثم الصق المحتوى).
2. على GitHub: Settings ← Developer settings ← Fine-grained tokens ← أنشئ رمزاً لهذا المستودع فقط بصلاحية **Contents: Read and write**.
3. على Netlify: Site configuration ← Environment variables، أضف:
   - `ADMIN_PASSWORD` — كلمة مرور اللوحة (12 حرفاً فأكثر)
   - `SESSION_SECRET` — نص عشوائي طويل (32 حرفاً فأكثر)
   - `GITHUB_TOKEN` — الرمز من الخطوة 2
   - `GITHUB_REPO` — مثل `waleedmmh/site` (اسم المستخدم/المستودع)
   - `GITHUB_BRANCH` — اختياري، الافتراضي `main`
4. أعد النشر (Deploys ← Trigger deploy)، ثم افتح `/admin/` وسجّل الدخول، وراجع تبويب **حالة الإعداد**: كل البنود يجب أن تكون ✔.
5. بريد إشعارات النموذج: Netlify ← Forms ← Form notifications ← Email notification ← `waleedmmh789@gmail.com`. (لا يمكن ضبطه من الكود.)

## كيف تعمل اللوحة
- تعديل التطبيقات والموقع من اللوحة **يكتب ملفات JSON في GitHub (commit)**، فيعيد Netlify البناء تلقائياً ويظهر التغيير بعد نحو دقيقة. المصدر الوحيد للحقيقة يظل ملفات JSON، فيمكنك أيضاً تعديلها يدوياً كما قبل.
- نفس حراسة البناء تعمل في اللوحة: لا يُحفظ تطبيق «منشور» بلا `play_url` أو `apk`، ولا روابط غير https، ولا صور بامتداد غير png/jpg/webp (الحد 2MB، والـ SVG ممنوع).
- ملفات APK لا تُرفع هنا: استضفها خارجياً وضع الرابط والبصمة.
- الجلسة 12 ساعة، وتُحجب المحاولات الخاطئة بعد 8 في الساعة.

## رفع APK لتعبئة بيانات التطبيق
- في اللوحة ← التطبيقات ← «+ تطبيق جديد» (أو «تعديل») أول قسم هو **رفع ملف APK**. اختر الملف فيُقرأ **على جهازك داخل المتصفح** ولا يُرسل لأي خادم (لذلك لا يتعارض مع حدود Netlify ولا مع CSP).
- يُعبَّأ ما هو مكتوب فعلاً داخل الملف: **الاسم** (إن كان فارغاً) والمعرّف المقترح، **الإصدار**، **الحجم**، **أقل أندرويد** (بالعربية والإنجليزية)، **بصمة SHA-256**، تاريخ اليوم كـ«آخر تحديث»، سطر في سجل الإصدارات، و**قائمة الأذونات** في السياسة (إن كانت فارغة) مع تعريف كل إذن في أندرويد.
- **لا يُكتب** وصف ولا تصنيف ولا بنود «البيانات المجمعة» و«الطرف الثالث» و«الاحتفاظ» و«الأطفال» و«الحذف»: هذه قرارك أنت. وتبقى السياسة مسودة حتى تفعّل الاعتماد. ما كتبته بنفسك لا يُستبدل؛ وإن اختلفت أذونات سياستك عن أذونات APK تظهر ملاحظة بالفرق.
- تظهر تنبيهات مستخرجة من AndroidManifest فقط (خدمة VPN، خدمة وصول، إعلانات Google، Firebase، مكتبات تتبع...) لتذكّرك بما يجب شرحه في السياسة. غياب التنبيه لا يعني غياب المكتبة أو السلوك، فالفحص لا يقرأ الشيفرة المجمّعة.
- **الاستضافة**: لا يخزّن الموقع ملف APK. ارفعه لاستضافة ثابتة (مثل GitHub Releases) وضع رابطه في «رابط تنزيل APK» (https). ارفع **الملف نفسه** دون إعادة توقيع أو ضغط، وإلا لن تطابق البصمة ويفشل `verify-apk.js` عند البناء. والحفظ يرفض بصمة بلا رابط.
- الملفات المدعومة: APK فقط (ليس AAB ولا XAPK). الملفات الكبيرة جداً قد لا تتسع لذاكرة بعض الهواتف، وعندها تظهر رسالة.

## اللغات
- لكل تطبيق حقل `i18n` فيه ترجمات لكل لغة (الاسم، الوصف، المميزات، **وسياسة الخصوصية**). الحقل غير المترجم يعود للأصل ويظهر تنبيه «لم تُترجم بعد».
- **سياسة الخصوصية لا تعود لنص لغة أخرى أبداً**، وتبقى «مسودة» في كل لغة حتى تُفعّل `approved` في ترجمتها.
- لإضافة لغة (مثلاً الفرنسية): انسخ `en.lang.json` إلى `fr.lang.json` وترجمه، ثم أضف `{ "code": "fr", "name": "Français", "dir": "ltr" }` إلى `languages` في `site.json`. تظهر تلقائياً في القائمة وفي اللوحة (تبويب ترجمة جديد لكل تطبيق).

## الإحصائيات
- تُعدّ مشاهدات الصفحات ونقرات أزرار التنزيل كأرقام يومية مجمّعة، **بلا كوكيز ولا عنوان IP**، وتُتجاهل مع إشارة «عدم التتبع» وعلى localhost والروبوتات المعروفة.
- «نقرات التنزيل» ليست عدد التثبيتات؛ التثبيتات الفعلية في Google Play Console.
- الأرقام تقريبية (قد يضيع عدّ نادر عند ازدحام نفس اللحظة).

## التقييمات
- تظهر فقط لتطبيقات «منشور» و«قيد الاختبار». كل تقييم يبقى **بانتظار المراجعة** حتى تعتمده من اللوحة، ويمكنك الرد عليه أو رفضه أو حذفه.
- الحماية من الإزعاج: حقل فخ مخفي، وحد أدنى للزمن، و3 تقييمات يومياً لكل بصمة IP مجزّأة (تتغير يومياً ولا يمكن عكسها). لا يُطلب بريد ولا حساب.

## قبل النشر الرسمي: قائمة مراجعة
1. `site.json`: ضع `url` (عنوان الموقع الرسمي) إن لم يضبطه Netlify، وراجع البريد والروابط.
2. **سياسة خصوصية الموقع** (`/privacy/site/`): كُتبت لتصف ما يفعله الموقع فعلاً. راجعها، ثم فعّل `policy.approved` وضع `policy.updated`.
3. **سياسة كل تطبيق**: نصوص «وليد ترجمة» مكتملة بالعربية والإنجليزية ومتطابقة البنية (يتحقق منها `npm test`)، لكنها ما زالت غير معتمدة عمداً. راجع كل بند وتأكد أنه يطابق ما يفعله التطبيق فعلاً، ثم فعّل `approved`. سياسة «وليد ترجمة» منقولة من ملفات الخصوصية داخل مشروع التطبيق، وبنود الخادم (الحذف الفوري للصوت، الاحتفاظ ساعة، سجلات IP) يجب أن تطابق خادمك الفعلي.
4. `waleed-adshield-mobile`: ما زال بلا أي بيانات (لا وصف ولا سياسة)، ولا يُختلق له شيء. صفحته تعرض الأقسام الستة «لم تُحدَّد بعد». املأه من اللوحة بمعلومات حقيقية عن عمل التطبيق وبياناته وأذوناته، بالعربية ثم الإنجليزية (تبويب ترجمة en).
5. ضع رابط الموقع الجديد في `PRIVACY_WEB_URL` داخل تطبيق وليد ترجمة (`util/Constants.kt`) حين تُعتمد السياسة.
6. هذه ليست استشارة قانونية؛ راجع النصوص بنفسك أو مع مختص إن لزم.

## الأمان والفحص
- `netlify.toml` يضبط CSP صارمة (لا سكربتات inline، ولا اتصال إلا بنفس النطاق) مع HSTS وPermissions-Policy.
- `verify-apk.js` يعمل قبل كل بناء: يحمّل كل رابط APK ويقارن بصمته بـ `sha256` المكتوبة، ويفشل البناء عند الاختلاف أو عند خطأ HTTP (وللتخطي: `SKIP_APK_VERIFY=1`).
- لا يمكن اعتماد سياسة خصوصية (`approved`) وفي حقولها نقص؛ يفشل البناء واللوحة.
- `npm test` يشغّل 22 اختباراً: البناء، الروابط الداخلية، اللغات، حراسة البيانات، XSS، رؤوس الأمان، واجهة الـ API، صحة رابط النشر، اتساق canonical وhreflang وsitemap وrobots.txt، وتطابق ترجمات سياسات الخصوصية مع أصلها، وقارئ APK وتعبئة نموذج لوحة التحكم منه (على APK تجريبي يُبنى داخل الاختبار).
- `site.json` ← `url`: ضع عنوان الموقع الرسمي ليُنشأ sitemap محلياً (على Netlify يُضبط تلقائياً من متغير `URL`).

## رابطان مختلفان (لا تخلط بينهما)
- **`official_url`** = الموقع الرسمي المرجعي (حالياً صفحة Google Sites). يظهر في التذييل وفي بيانات SEO (`sameAs`) فقط. **لا يدخل** في canonical أو sitemap أو hreflang لأن صفحاته ليست صفحات هذا المشروع.
- **`url`** = رابط نشر هذا الموقع البرمجي (Netlify أو دومينك عليه). هو الذي تُبنى عليه ملفات SEO. اتركه فارغاً ليُؤخذ تلقائياً من Netlify.

## رابط نشر الموقع (مكان واحد)
- يُحدَّث من **لوحة التحكم ← بيانات الموقع**، أو من `site.json` ← `url`، أو من متغير البيئة `SITE_URL` في Netlify. لا يوجد أي دومين مكتوب في الشيفرة أو الصفحات.
- ترتيب الأولوية: `site.json` ثم `SITE_URL` ثم `URL` الذي يضبطه Netlify تلقائياً. لذلك إن أردت أن يتحكم `SITE_URL` فاترك `url` في `site.json` فارغاً (`null`).
- الصيغة المقبولة: عنوان النطاق فقط، مثل `https://waleedmmh.netlify.app` أو دومينك الخاص. تُحذف الشرطة الأخيرة تلقائياً. **يُرفض** (ويفشل البناء ولا تُحفظ اللوحة): `http://`، وأي مسار أو استعلام (مثل `/en`)، وأي رابط على `google.com`، لأن رابط Google Sites مكانه `official_url` فقط.
- بعد وضعه تُنشأ تلقائياً روابط canonical وhreflang وog:url وsitemap.xml وسطر Sitemap في robots.txt، وكلها من هذا الرابط وحده. وإن كان فارغاً لا تُنشأ ولا يُختلق شيء.
- للتأكد: `npm run check` يعرض الرابط المعتمد ومصدره، ويشرح سبب الرفض إن كان غير صالح.
- لاحقاً: حدّث `PRIVACY_WEB_URL` داخل تطبيق وليد ترجمة بالرابط الجديد.

## فحص الجاهزية قبل النشر
`npm run check` يطبع ما تبقى (الرابط، السياسات المسودة أو الناقصة بكل لغة، روابط التنزيل)، و`node check.js --strict` يفشل إن بقي أي بند، فيصلح للاستخدام قبل النشر الرسمي.
